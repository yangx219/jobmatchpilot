# Motion Guidelines — 克制、可理解、可关闭

JobMatchPilot 的动效用于解释层级、状态和操作结果，不用于填充空白。营销页面允许更强的叙事性，工作台优先保证阅读和操作效率。

## 时间与缓动

| 场景 | 时长 | 用途 |
|---|---:|---|
| 即时反馈 | 120–160ms | hover、pressed、focus 邻近反馈 |
| 标准过渡 | 180–220ms | 状态、颜色、简短展开 |
| 页面或面板进入 | 240–300ms | 一次性层级建立 |

默认采用平稳的 ease-out；不使用弹跳来表现严肃状态。列表 stagger 的总延迟不得超过 120ms，不能让后续内容等待用户。

## 实现规则

- 优先使用 CSS；复杂的、与手势或状态机同步的动画才评估现有 `@react-spring/web`。
- 优先动画化 `transform` 和 `opacity`，避免触发布局计算的属性。
- 服务端输出必须默认包含完整内容；动效加载失败不能隐藏信息。
- 动效不能是状态的唯一表达方式，必须同时具有文字、图标或颜色之外的明确提示。
- 不使用循环装饰动画；运行中状态如需循环，必须足够轻且有可读文本。
- 新增动画库需要记录依赖成本、无法用现有能力实现的原因和移除方案。

## 无障碍

`prefers-reduced-motion: reduce` 下关闭所有非必要 animation 和 transition。即使动效被关闭，焦点、状态、顺序和内容都必须保持一致。不得对主体文字使用打乱、消散、逐字漂移或影响屏幕阅读器语义的实现。

## 评审问题

1. 这段动效解释了什么？删除后若没有理解损失，默认删除。
2. 是否延迟了阅读、点击或表单输入？
3. 是否在手机、慢速设备和长文本下稳定？
4. reduced-motion 是否真正无动画，而不只是缩短时长？
5. 来源、许可证和依赖是否可追溯？
